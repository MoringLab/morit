`C:\Users\louis\Documents\.dev\Luverse_moring\moring_allin1_app`에서 Flutter 기반의 **Android 우선 개인용 올인원 저장 앱 Morit**을 실제 실행 가능한 상태로 구현하라.

Morit은 인터넷과 일상에서 발견한 콘텐츠를 폴더별로 수집·관리하는 개인 공간이다. 초기 MVP에서는 다음 기능을 구현한다.

* Supabase 로그인
* 폴더 생성·수정·삭제
* 메모, 링크, 북마크 저장과 메모·오늘 할 일·알림의 사진·영상·파일 첨부
* 미디어 다운로드 및 기록
* 알림과 일정
* 최근 항목, 빠른 메모, 다운로드 상태
* 검색, 정렬, 이동, 삭제
* 오프라인 저장 및 자동 동기화
* 계정, 저장 공간, 다운로드, 알림, 개인정보 설정

YouTube, X, Threads, Instagram, Discord, 브라우저 등에서 링크·텍스트·사진·영상을 Android 공유 기능으로 전달하면 전체 앱을 열지 않고 `다른 앱 위에 표시` 오버레이를 즉시 띄워라.

오버레이에서는 다음 작업이 가능해야 한다.

* 콘텐츠 미리보기 및 정보 확인
* 저장할 폴더 선택
* 메모 추가
* 링크 또는 파일 저장
* 미디어 품질 선택 및 다운로드
* 취소

앱은 Flutter로 개발하고, Android 공유 수신, 오버레이, 백그라운드 다운로드 등 필요한 기능은 Kotlin 네이티브로 연동하라. 추후 iOS Share Extension과 Swift 네이티브 기능을 추가할 수 있도록 공통 로직과 플랫폼 전용 코드를 분리한다.

미디어 다운로드는 검증된 HTTPS 원본의 기기 직접 다운로드를 우선한다. 임의 URL 백엔드 프록시는 SSRF 방지용 고정 egress allowlist, DNS 재검증, timeout, 크기 제한, 사용자 quota가 구현되기 전까지 제공하지 않는다.

다운로드는 진행률, 취소, 재시도, 백그라운드 실행, 기록 관리를 지원해야 한다.

Supabase MCP를 사용해 프로젝트 `goiyqbdsfoauumuopkno`의 `morit` 스키마에서 필요한 테이블, 관계, 인덱스, RLS 정책과 Storage 구조를 설계·적용하라. 기존 인증 시스템과 다른 스키마의 데이터는 수정하지 말고 그대로 사용한다. 사용자 데이터와 파일은 계정별로 완전히 분리한다.

Android UI는 최신 Material Design 3와 Toss의 간결한 UX를 결합해 상용 앱 수준으로 제작한다. 과도한 카드, 그라데이션은 피하고 빠른 저장과 탐색에 집중한다. 추후 iOS에서 Liquid Glass 디자인으로 교체할 수 있도록 디자인 시스템을 분리한다.

메모, 다운로드, 링크, 파일, 알림을 서로 독립된 앱처럼 구현하지 말고, 공통 폴더와 항목 모델 위에 새로운 콘텐츠 유형을 쉽게 추가할 수 있는 확장형 구조로 설계하라.

먼저 유사 앱과 Android 공유·오버레이 구현 방식을 조사하고 계획을 수립한 뒤 개발을 시작한다. 샘플 UI나 가짜 데이터가 아니라 로그인, 폴더, 저장, 공유 오버레이, 다운로드, Supabase 동기화가 실제로 동작하는 완성도 높은 MVP를 구현하라.

## APK 우선 완료 기준

문서, 목업, AAB, iOS보다 Android 실기기에 바로 설치할 수 있는 범용 APK를 최우선 산출물로 제공하라.

* `flutter pub get`, `flutter analyze`, `flutter test`, `flutter build apk --release`를 오류 없이 완료한다.
* 서명된 APK를 `dist/morit-release.apk`로 제공하고 SHA-256 체크섬, 파일 크기, 빌드 시각을 기록한다.
* Android 실기기 또는 에뮬레이터에서 `adb install -r dist/morit-release.apk`로 설치한 뒤 최초 실행과 핵심 기능을 직접 검증한다.
* 로그인과 세션 복원, 폴더 CRUD, 항목 저장·검색·이동·삭제, 다른 앱의 공유 수신, 다운로드 진행·취소·재시도, 앱 재시작, 오프라인 저장 후 재연결 동기화를 스모크 테스트한다.
* 키스토어, 비밀번호, Supabase 서버 키를 저장소나 APK에 포함하지 않는다. 클라이언트에는 공개 가능한 anon/publishable 키만 사용하고 RLS를 보안 경계로 삼는다.
* 지원하지 않는 사이트나 DRM 콘텐츠를 우회하지 말고 링크 저장으로 안전하게 대체하며, 실패 원인과 복구 방법을 사용자에게 표시한다.
* 실행하지 않은 검증을 통과했다고 보고하거나 근거 없이 무결점을 주장하지 않는다. 최종 응답에는 APK의 절대 경로, 체크섬, 설치 방법, 실제 테스트 결과, 남은 제한 사항을 먼저 안내한다.

## 오늘 할 일·폴더·첨부 UX

기존 Flutter 구조와 사용자 데이터를 보존하면서 다음 동작을 실제 데이터와
연결한다.

* 홈의 오늘 할 일은 최대 3개와 `모두 보기`를 표시한다.
* ongoing 알림은 기존 목록을 유지하면서 각 행의 완료 체크·수정과 우측 상단
  `추가`·`목록`을 제공한다.
* 알림 전체, `목록`, 앱의 `모두 보기`는 같은 Material 3 중앙 목록 모달을
  열고 `추가`는 그 모달의 입력 UI까지 연다.
* 모달의 추가·수정·삭제·완료·순서 변경을 앱, 알림, 로컬 캐시와 DB에 즉시
  반영한다.
* 완료 항목은 즉시 숨기지 않고 노란 형광펜+취소선 애니메이션으로 당일
  유지한다. 날짜가 바뀌면 완료 항목은 제외하고 미완료 항목은 설정에 따라
  이월한다.
* 잠금화면 편집 정책은 `기기 잠금 해제 후`, `잠금 없이`, `Morit PIN`을
  지원한다. 특수 오버레이 권한이 없거나 플랫폼이 제한하면 안전한 Activity
  화면으로 대체한다.
* 오늘 할 일 이월, 완료 표시, 정렬, 알림 개수, 애니메이션과 잠금 정책을
  설정에서 바꿀 수 있게 한다.

사진·영상·일반 파일은 독립 콘텐츠 종류가 아니라 메모 첨부로 통합한다.
첨부 DB 행과 Storage 객체는 안정적인 UUID와
`user_id/item_id/attachment_id/file.<safe_extension>` ASCII 경로로 묶는다.
사용자에게 보이는 원본 파일명은 DB `file_name` 메타데이터에 별도로 보존하고,
pending/uploading/uploaded/failed/deleting 상태, 진행률, 명시적 재시도,
안전한 실패 원인, 중복과 보상 삭제를 처리한다. 큰 파일은 재개 가능한
업로드를 사용한다. 기존 scalar
파일 항목은 ID·폴더·즐겨찾기·시간·Storage 경로를 보존한 채 손실 없이
메모+첨부로 이전한다.

메모·오늘 할 일·폴더는 드래그해 폴더로 이동할 수 있어야 하며 하위 폴더를
지원한다. 자기 자신 또는 자손 폴더로 이동하는 순환 참조는 Flutter와 DB
양쪽에서 막는다. 상세 bottom sheet는 전체 가로 너비를 사용한다.

즐겨찾기는 홈의 독립 강조 섹션과 전체 보기로 제공한다. 설정은 알림,
오버레이, 잠금화면, PIN, 이월, 완료 표시, 정렬, 즐겨찾기, 폴더, 화면 밀도,
Wi-Fi 다운로드와 자동/수동 동기화를 포함한다. 계정 화면의 Supabase 홍보
문구는 제거하고 `계정 관리`는 `https://account.moring.co/my`를 연다.

공통 데이터·동기화·미디어 Provider·UI 상태는 Android 네이티브 코드와
분리해 iOS Share Extension과 Widget/Live Activity 구현을 같은 계약에
연결할 수 있게 한다. Android 고유 알림/잠금화면 동작을 공통 계층에
하드코딩하지 않는다.

## 통합 첨부·편집 UI

`+ 저장`의 최상위 종류에서는 사진·영상·파일을 제거한다. 메모, 오늘 할 일,
알림의 생성·수정 화면에서 시스템 파일 선택기로 사진·영상·문서를 여러 개
첨부하고 저장 전까지 추가·제거할 수 있어야 한다. 취소 시 항목이나 기존
첨부를 변경하지 않고, 저장할 때 항목·첨부 변경을 한 번에 로컬 캐시와
Supabase에 반영한다. 링크와 기존 legacy 미디어 항목의 표시 호환성은
유지한다.

모든 폼은 동일한 Material 3 입력창, 16px control radius, 50px 액션 높이,
20px 좌우 여백을 사용한다. 취소와 저장은 같은 행에서 동일 크기로 표시하고,
상세 bottom sheet는 전체 가로 너비와 좌측 정렬을 사용한다. 폴더 팔레트의
마지막 항목은 HSV 기반 사용자 지정 색상 선택기를 연다. 오늘 할 일 수정은
목록 위에 두 번째 dialog를 쌓지 않고 같은 panel의 수정 상태로 전환한다.

홈 브랜드 로고는 `docs/app_logo_transparent.png`를 사용한다. Android와 향후
iOS 런처 아이콘은 플랫폼별 안전 영역과 배경 규격에 맞춘 별도 에셋으로 생성한다.

## 폴더 이동·홈·플랫폼 Provider

파일·메모·오늘 할 일·폴더를 길게 누르면 현재 계층을 반영한 폴더 트리를
표시한다. 폴더 위에 600ms 머무르면 자동으로 펼치고, 트리 상·하단에서는
자동 스크롤한다. 루트와 상위 폴더도 드롭 대상으로 제공하며 자기 자신,
자기 자손, 존재하지 않거나 소유하지 않은 위치는 비활성화한다. 드롭 전에
전체 이동 경로를 보여주고 이동 후 Snackbar 실행 취소를 제공한다.

찾기 탭의 루트 목록에는 폴더 안의 항목을 섞지 않는다. 폴더 화면 상단에는
현재 폴더명 하나만 표시하고, 조상 경로는 사용자가 요청할 때만 접힌 메뉴로
열어 상위 폴더로 이동한다.

홈의 `빠른 저장`과 `오늘 할 일`은 같은 디자인 토큰을 사용한다. 좌우 22px,
surface radius 18px, 기본 행 높이 64px, 40px 아이콘 컨테이너와 동일한
텍스트 계층을 적용한다. 붙여넣기→입력 확인→전송 흐름을 한 surface 안에서
완결하고, 0개·1개·여러 개의 오늘 할 일 상태에서도 행 정렬이 흔들리지 않게
한다. 즐겨찾기는 강조 surface로 유지하되 최근 항목은 부모 카드를 두지 않고
투명한 행과 구분선만 사용한다.

루트·홈에서 시작한 드래그는 화면에 보이는 폴더 타일에 직접 놓는다. 폴더
화면 내부에서 시작한 드래그만 전체 계층과 루트·상위 경로가 있는 `폴더로
이동` 바텀시트를 표시한다.

다운로드 분석은 Provider 레지스트리로 분리한다. YouTube, Instagram,
Facebook, Threads, TikTok, X, Bluesky, Reddit, Pinterest, Snapchat,
LinkedIn, Tumblr, Twitch, Vimeo, Dailymotion, Discord, Telegram,
KakaoStory, Naver Cafe, Naver Blog, Naver Band, LINE, Medium, Substack,
WordPress, Behance, Flickr, Imgur, SoundCloud의 도메인과 링크 형식을
판별한다. 유사 도메인을 허용하지 않고, 로그인 필요·접근 거부·404·429·서버
오류·TLS·timeout·공개 미디어 없음의 실패 이유를 구분한다. 공개 페이지가
노출한 HTTPS 직접 파일만 저장하며 로그인 우회, DRM 해제, 서명 생성,
HLS/DASH 재조합은 수행하지 않는다.
